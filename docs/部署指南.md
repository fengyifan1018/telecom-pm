# Docker 部署指南

> 前提：服务器已安装 Docker 与 Docker Compose 插件（`docker compose version` 可用）。
> 未安装：`curl -fsSL https://get.docker.com | sh`

## 1. 获取代码

```bash
git clone https://github.com/fengyifan1018/telecom-pm.git
cd telecom-pm
```

## 2. 配置环境变量

```bash
cp .env.example .env
# 生成强密钥并填入 SECRET_KEY（必填，弱密钥会拒绝启动）
python3 -c "import secrets; print(secrets.token_hex(32))"
vi .env
```

| 变量 | 说明 |
|---|---|
| SECRET_KEY | **必填**，≥32 位强随机；DEBUG=false 下弱密钥拒绝启动 |
| DATABASE_URL | 保持默认（容器内 /app/data/telecom.db，挂载宿主机 ./data） |
| APP_PORT | 对外端口，默认 8080 |
| TZ | 时区，影响每日快照/超期扫描的本地时间，默认 Asia/Shanghai |

## 3. 启动

```bash
docker compose up -d --build
docker compose ps            # 两容器 healthy/running
curl http://127.0.0.1:8080/api/health   # {"status":"ok"}
```

浏览器访问 `http://服务器IP:8080`。

## 4. 初始化数据（二选一）

```bash
# A. 演示数据（6 个演示账号，密码 123456——仅试用，用完改密或清库）
docker compose exec backend python -m app.seed.run_seed

# B. 生产：只建必要种子（模板+客户+权限），然后用"用户管理"页创建真实账号
docker compose exec backend python -m app.seed.run_seed
```

> 首个管理员：种子含 admin/123456（若已被使用则用演示账号登录），
> **登录后立即在「用户管理」改密**，并在「权限管理」复核默认矩阵。

## 5. 备份与恢复

```bash
./deploy/backup.sh          # 备份到 backups/（默认保留 14 份），建议 crontab 每日执行
# crontab -e 加一行（每天 02:00）：
# 0 2 * * * cd /path/to/telecom-pm && ./deploy/backup.sh >> backups/backup.log 2>&1

# 恢复：停后端 → 覆盖数据文件 → 起后端
docker compose stop backend
cp backups/telecom_YYYYMMDD_HHMMSS.db data/telecom.db
docker compose start backend
```

## 6. 升级

```bash
git pull
docker compose up -d --build   # entrypoint 自动跑幂等迁移
```

## 7. 常见问题

- **启动即退出，日志出现 "SECRET_KEY 不安全"**：未配置强密钥，见第 2 步
- **上传的附件在哪**：宿主机 `./data/uploads/`（随 data 卷持久化）
- **数据在哪**：宿主机 `./data/telecom.db`，备份请用第 5 步脚本（直接 cp 正在写的库有一致性风险）
- **改了端口**：`.env` 的 APP_PORT 后 `docker compose up -d` 重建 frontend 容器
- **HTTPS**：建议外层再放一层 nginx/caddy 或云负载均衡终止 TLS，反代到 APP_PORT

## 任务与协作

### 1. 任务协作人（多人与单任务）⭐ 2026-09-03 登记

**需求来源**：一个任务能否同时指派给多人？现状不支持（`assignee_id` 单列，指派为覆盖式）。

**已定方案（方案 A）**：保持单人负责制不变（进度/审核口径清晰），新增多选**协作人**：
- 协作人可查看任务、参与评论、接收任务状态变更通知（并入 `notify_watchers` 分发逻辑）
- 不影响 blocks 卡点、不参与进度报量、不出现在"负责人"列（或以次要身份显示）
- 改造点：`task_collaborators` 关联表、指派抽屉多选、任务可见性口径扩展（协作人可见）

**验收要点**：协作人能看到任务并收通知；通知不重复（负责人/审核人/协作人去重）；移除协作人后停止通知。

**为什么不做多负责人**：多人负责=无人负责；多人协作的主流解法是拆任务（模板已细粒度）或协作人机制（Jira/OpenProject 同理）。

### 2. 用户组赋能（按组指派 / 按组通知）P2

现状：用户组是纯名册（无任何业务消费），仅一个演示组。二选一：
- 赋能：任务指派可选"组"（组内派单）+ 通知支持发给组 —— 通信行业按工种派单的真实工作流
- 若确认无按组需求，则从菜单移除用户组管理，减少困惑

**依赖**：先决定用户组的定位（赋能 or 移除）。

### 3. 批量操作 P1

任务列表多选，批量指派 / 批量修改优先级 / 批量修改截止日。54 个任务逐个操作是真实痛点。

### 4. 手工新建任务入口 P2

任务目前只能由模板立项生成，无法临时插入任务（如"配合客户审计"）。需按阶段挂载 + 指派 + 排期。

### 5. 多级审核 / 会签 P3

大额采购等场景需要双人审核。reviewer 单人模型需扩展为审核链。

## 管理驾驶舱

### 6. 趋势对比（较上月）P1

工作台统计卡的"较上月 ↑2"需要**每日数据快照**：新增快照表 + 每日定时任务（调度器已就绪，加一个 job）+ 快照查询。做完后趋势、基线、燃尽图共享同一数据源。

### 7. 风险登记册 P1

替代目前的"升级+超期"代理版风险区：主动登记风险（名称/概率×影响/应对措施/负责人/状态），项目详情风险区与工作台风险预警卡切换数据源。可参考 OpenProject 风险类型工作包。

### 8. 基线对比 P2

立项时保存排期基线快照，甘特图/详情叠加显示"计划 vs 当前"偏移。依赖：预排期已就绪；与趋势快照共享机制可省一半。

### 9. 本周视图 / 截止日期范围筛选 P2

任务列表加"截止范围"筛选（预置本周），工作台加"本周截止"区块。（已明确暂缓，用户提出时优先做）

### 10. 里程碑模型 P2

里程碑作为独立实体（日期+名称+所属项目+状态），甘特图/看板/工作台"近期里程碑"卡挂靠。设计稿已画但被暂缓。

### 11. 阶段门禁评审 P2

关键阶段（如施工开通前）激活需 PM 确认交付物齐套才放行，替代纯自动激活。改动点在 `_activate_next_phases` 前置一道人工 gate。
